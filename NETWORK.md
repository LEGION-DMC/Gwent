# Сетевая игра через интернет

Раньше сетевой режим умел соединять только игроков в одной локальной сети:
в `RTCPeerConnection` не было ICE-серверов, а параметры соединения нужно было
вручную копировать из окна в окно.

Теперь игра работает через интернет **без своего сервера и без покупок**.

## Как играть

1. Оба игрока открывают игру (например, GitHub Pages).
2. «ИГРАТЬ» → «ИГРОК ПРОТИВ ИГРОКА».
3. Хост нажимает **«СОЗДАТЬ КОМНАТУ»** и получает короткий код, например `K7M2QX`.
4. Гость нажимает **«ВОЙТИ ПО КОДУ»**, вводит код и жмёт «ПОДКЛЮЧИТЬСЯ».
5. Дальше всё как раньше: выбор фракции, сборка колоды, партия.

Код можно передать в мессенджере, голосом или любым другим способом.
Никакой регистрации и настроек не требуется.

## Как это работает

- **Сигнализация** — через бесплатный публичный сервис [ntfy.sh](https://ntfy.sh).
  Хост публикует SDP-приглашение в тему `gwent-v1-<код>-o`, гость читает его
  и публикует ответ в тему `gwent-v1-<код>-a`. Это обычные HTTPS/WebSocket
  запросы, поэтому работает на GitHub Pages без бэкенда.
- **Сама игра** идёт напрямую между браузерами по WebRTC DataChannel.
  ntfy.sh видит только параметры соединения (SDP), но не игровой трафик.
- **STUN** (`stun.l.google.com`, `stun.cloudflare.com`) помогает браузерам
  узнать внешний адрес и «пробить» домашний NAT. Именно этого раньше не хватало
  для игры через интернет.

## Ограничения

WebRTC не может соединить две сети, в которых обе стороны за «строгим» NAT
(например, мобильный интернет с CGNAT или некоторые корпоративные сети).
В таких случаях нужен **TURN-сервер** — он пересылает трафик через себя.

TURN не обязателен: у большинства домашних подключений соединение устанавливается
напрямую. Если нужно гарантированное соединение, подойдёт любой бесплатный
TURN с лимитом трафика (например, Metered/Open Relay — бесплатный аккаунт,
20 ГБ в месяц). Полученные `iceServers` можно добавить одним из способов:

**Способ 1 — через консоль браузера (быстро, только для этого браузера):**

```js
localStorage.setItem('gwentIceServers', JSON.stringify([
    { urls: 'stun:stun.l.google.com:19302' },
    { urls: 'turn:ваш.turn.сервер:3478', username: 'логин', credential: 'пароль' }
]));
location.reload();
```

**Способ 2 — навсегда, в коде:** отредактируйте `DEFAULT_ICE_SERVERS`
в начале `network/network.js`.

## Ручной режим

Вкладка **«ВРУЧНУЮ (SDP)»** — старый способ обмена кодами приглашения и ответа.
Он оставлен как запасной: работает и через интернет (STUN теперь включён),
но требует передать два длинных кода туда-обратно.

## Приватность

- Имя темы ntfy — это фактически пароль. Код комнаты случайный (6 символов),
  поэтому угадать тему сложно, но она **не защищена паролем**: любой, кто знает
  код, может прочитать SDP (там есть IP-адреса и отпечатки DTLS).
- Сообщения в ntfy.sh хранятся в кэше около 12 часов.
- Игровой трафик зашифрован DTLS и идёт напрямую между игроками.

## Файлы

- `network/signaling.js` — обмен SDP через ntfy.sh (комнаты, чанки, переподключение).
- `network/network.js` — ICE-серверы, автоматическое подключение по коду,
  ручной режим и вся синхронизация партии.
- `network/network.css` — оформление лобби.
- `index.html` — подключение `signaling.js` перед `network.js`.
